# Feature Detail: Knowledge Graph Construction & Storage

**Feature ID**: 002
**Name**: Knowledge Graph Construction & Storage
**Description**: Entity and relation extraction from documents, incremental knowledge graph construction, and multi-backend persistent storage.
**Status**: Implemented
**Created**: 2026-06-23
**Last Updated**: 2026-06-23

## Overview

Core to LightRAG is the ability to extract entities and relationships from text chunks, build an incremental knowledge graph, and persist it across multiple storage backends. The KG subsystem supports both graph-native stores (Neo4j, NetworkX) and vector-capable stores for hybrid retrieval, with automatic storage migration on schema changes.

## Latest Review

Stable multi-backend KG storage with shared storage abstraction. Supports incremental updates, document deletion with KG regeneration, and storage migration framework.

## Key Changes

1. Entity/relation extraction with configurable LLM prompts and role-specific LLM config
2. Incremental KG construction with merge/update semantics
3. Multi-backend storage abstraction (PostgreSQL, Neo4j, MongoDB, Milvus, Qdrant, Redis, OpenSearch, Faiss, NetworkX, NanoVectorDB)
4. Storage migration framework for schema evolution
5. Document deletion with automatic KG regeneration

## Implementation Notes

- `lightrag/kg/shared_storage.py` defines the common storage interface
- Each backend implements the interface in its own `*_impl.py` file
- `storage_migrations.py` handles schema versioning and migration
- KG operations are async-first for backend compatibility

## Future Evolution Suggestions

- Graph versioning and snapshot/restore
- Cross-backend migration tooling
- Knowledge graph visualization improvements
