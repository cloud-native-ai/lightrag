# Feature Detail: Test Coverage Reporting

**Feature ID**: 013
**Name**: Test Coverage Reporting
**Description**: Automated test coverage measurement and reporting integrated into CI pipeline, with coverage thresholds enforced on PRs.
**Status**: Draft
**Created**: 2026-06-23
**Last Updated**: 2026-06-23

## Overview

While LightRAG has a comprehensive test suite with pytest, there is no automated coverage measurement or reporting. Adding coverage tracking would help identify untested code paths, enforce minimum coverage thresholds on new code, and provide visibility into test quality trends over time.

## Latest Review

Initial draft — gap identified during DFX analysis (DFT: Design for Testability).

## Key Changes

1. Integrate `pytest-cov` or `coverage.py` into the test dependencies
2. Configure coverage measurement with per-module thresholds in `pyproject.toml`
3. Add coverage reporting step to CI test workflow
4. Enforce coverage decline prevention on PRs (e.g., via Codecov or Coveralls)
5. Generate coverage badges for README

## Implementation Notes

- Requires `pytest-cov` added to test dependencies
- CI workflow needs coverage artifact upload
- Coverage thresholds should start modest and increase over time
- Consider excluding auto-generated and deprecated code paths

## Future Evolution Suggestions

- Per-subsystem coverage targets (e.g., kg > 80%, parser > 70%)
- Mutation testing for critical paths
- Coverage trend dashboard
