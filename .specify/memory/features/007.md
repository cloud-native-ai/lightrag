# Feature Detail: LLM Provider Integration

**Feature ID**: 007
**Name**: LLM Provider Integration
**Description**: Multi-provider LLM backend support with role-specific configuration: OpenAI, Anthropic, Google Gemini, Azure, Bedrock, Ollama, and 10+ other providers.
**Status**: Implemented
**Created**: 2026-06-23
**Last Updated**: 2026-06-23

## Overview

LightRAG supports a wide range of LLM providers for extraction, query, keyword generation, and vision tasks. Each role (EXTRACT, QUERY, KEYWORDS, VLM) can be configured independently with different models, endpoints, and parameters. Provider implementations are unified behind a consistent interface.

## Latest Review

14+ LLM providers supported with role-specific configuration. Binding options allow per-role model selection. Deprecated providers moved to `deprecated/` subdirectories. LlamaIndex integration for broader provider compatibility.

## Key Changes

1. 14+ LLM providers: OpenAI, Anthropic, Gemini, Azure, Bedrock, Ollama, NVIDIA, LMDeploy, Zhipu, Jina, VoyageAI, HuggingFace, LOLLMS, LlamaIndex
2. Role-specific LLM configuration: EXTRACT, QUERY, KEYWORDS, VLM each independently configurable
3. Unified provider interface with `binding_options.py` for model selection
4. Vision utilities (`_vision_utils.py`) for multimodal LLM support
5. Deprecated provider cleanup and migration path

## Implementation Notes

- Each provider is a module under `lightrag/llm/`
- `binding_options.py` maps roles to specific model configurations
- `llm_roles.py` defines the four role constants
- Environment variables drive provider configuration (`.env` file)
- LlamaIndex integration (`llama_index_impl.py`) extends compatibility

## Future Evolution Suggestions

- Provider health checking and automatic failover
- Provider response streaming
- Cost tracking and token usage monitoring per provider
