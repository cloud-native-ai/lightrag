# Feature Detail: Performance Benchmarking

**Feature ID**: 015
**Name**: Performance Benchmarking
**Description**: Automated performance benchmarking suite for ingestion throughput, query latency, and storage backend comparison.
**Status**: Draft
**Created**: 2026-06-23
**Last Updated**: 2026-06-23

## Overview

LightRAG processes documents through multi-stage pipelines (parsing, chunking, embedding, KG construction, storage) with multiple backend options. There is currently no systematic performance benchmarking to guide users in backend selection or to detect performance regressions.

## Latest Review

Initial draft — gap identified during DFX analysis (DFP: Design for Performance).

## Key Changes

1. Create benchmark harness for ingestion pipeline (docs/sec, tokens/sec)
2. Benchmark query latency across all four query modes
3. Cross-backend performance comparison (PostgreSQL vs Neo4j vs Milvus vs Qdrant)
4. Integrate benchmarks into CI for regression detection
5. Publish benchmark results in documentation

## Implementation Notes

- Use `pytest-benchmark` or custom harness for repeatable measurements
- Backend benchmarks require containerized backends in CI
- Performance targets should be documented per backend
- Consider warm-up/cold-start scenarios
- Token usage tracking for cost estimation

## Future Evolution Suggestions

- Scalability benchmarks with large document corpora
- Memory profiling for large knowledge graphs
- Latency percentile tracking (p50, p95, p99)
